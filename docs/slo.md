# SLO · SLI

# 1. 알림

## SLO

```
사용자가 설정한 시각으로부터 10분 안에 나간다
```

| | 목표 |
|---|---|
| 넘기면 안 되는 선 | 10분 |
| 그중 대부분 | p95 1분 이내 |

- 10분을 넘긴 것은 보내지 않고 버리므로 지연을 어기는 것과 알림이 사라지는 것이 같은 사건이다. 
- 10분인 근거는 다음과 같다.
```
그쯤까지는 "좀 늦었네" 지만 그 뒤로는 "고장났네" 로 읽힌다
재시도 3회가 1+2+4 로 7분을 쓰므로 그 안에 들어가야 한다
```
- 공식 기준은 없다. FCM 문서가 짧은 TTL 이 필요한 예로 캘린더 알림을 들지만 몇 분으로
하라는 말은 없다. **우리가 정한 값이다.**
  - `NotificationScheduler.VALID_MINUTES` 가 이 값이다.

- 유실은 다음과 같다.
```
설정한 알림은 반드시 나간다.  유실률 0 %
```

유실은 **10분을 넘겨 버려진 것**만 말한다. FCM 이 거부한 것(`FAILED`)은 유실이
아니다. 기록이 남고 사용자에게 설명할 수 있다.


## SLI

### 지표

```
alarm_delay_seconds     실제 발송 시각 − 울릴 시각
alarm_expired_total     10분을 넘겨 버려진 건수
alarm_sent_total        발송된 건수
```

지연 버킷은 통합검색과 같은 방식으로 둔다.

```
1분 · 5분 · 10분
```

### 계산

```
유실률 = expired / (sent + expired)
```

## 측정 상태

| | 로그 | 지표 |
|---|---|---|
| 지연 | 있다 | 없다 |
| 유실 | **없다** | 없다 |

- 지연은 로그로 계산된다. `발송시도` 줄의 `예정=` 이 울릴 시각이고 `발송성공` 줄에
  실제 시각이 찍힌다. 측정 스크립트(`06_latency.py`)가 그렇게 뽑는다.
  - 다만 **사람이 로그를 받아 돌려야** 하고 그라파나에 안 뜬다.
- 유실은 **어디에도 없다.** 만료된 알림은 조회에서 빠질 뿐 `FAILED` 로 바뀌지도, 로그가
  남지도 않는다.
  - 세려면 **그것을 집어서 표시하는 주체**가 있어야 하는데, 조회에서 빠진 뒤로는 아무도
    집으러 오지 않는다.


## 아직 안 정한 것

### 오차 예산

`99.9%` 같은 값을 안 정했다. 셀 수 있게 된 뒤에 정한다.

### 운영 약속으로 쓸 시점

지금은 **설계 기준**이다. *"이 조건을 만족하도록 만든다"* 이지 *"한 달에 몇 번까지
어겨도 된다"* 가 아니다. 실사용 트래픽이 쌓이면 옮긴다.

### 종일 일정

울릴 시각이 시작 날짜 오전 9시로 고정이다. 시간 설정 일정과 같은 10분을 적용하는 것이
맞는지 안 봤다.
